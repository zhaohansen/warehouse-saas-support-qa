# Python 学科知识手册

## 1. 变量与数据类型

Python 是动态类型语言，变量本身没有类型，变量只是对象的一个引用。赋值语句 `a = 10` 做的事情是：在内存中创建整数对象 10，再让名字 a 指向它。因此 `a = "hello"` 不会报错，只是把 a 改为指向另一个字符串对象。

内置数据类型分为不可变与可变两类。不可变类型包括 int、float、str、tuple、frozenset，可变类型包括 list、dict、set。不可变对象一经创建内容就不能修改，所谓"修改"其实是创建了新对象。

类型判断用 `type()` 得到确切类型，用 `isinstance()` 判断是否属于某个类及其子类。工程上更推荐 `isinstance()`，因为它对继承友好。

## 2. 可变与不可变对象、深浅拷贝

赋值 `b = a` 只复制引用，a 与 b 指向同一个对象。对可变对象来说，通过 b 修改内容，a 看到的结果也会变。

浅拷贝由 `copy.copy()`、列表的 `list()`、切片 `a[:]` 产生。浅拷贝会创建新的外层容器，但容器内部的元素仍然是原来的引用。所以列表里嵌套列表时，改内层列表两边都会受影响。

深拷贝由 `copy.deepcopy()` 产生，它递归复制所有层级的对象，两份数据完全独立。深拷贝需要处理循环引用，性能开销明显大于浅拷贝。

判断标准：容器里的元素全是不可变对象时，浅拷贝足够；存在嵌套可变对象且需要互不影响时，必须用深拷贝。

## 3. 列表与字典的底层实现

列表底层是动态数组，内部维护一块连续内存和已用长度、容量两个计数。追加元素时如果容量足够，直接在末尾写入；容量不足则按约 1.125 倍扩容并整体搬迁。因此末尾追加的平均复杂度是 O(1)，而在头部插入或删除是 O(n)。

字典底层是哈希表，采用开放寻址法解决冲突。Python 3.6 之后字典在内存中额外维护一个紧凑的索引数组，使键值对按插入顺序连续存放，这也是"字典有序"这一特性的来源。

字典查找的平均复杂度是 O(1)，最坏情况在大量哈希冲突时退化。作为键的对象必须可哈希，即实现了 `__hash__` 与 `__eq__`，且哈希值在生命周期内不变，所以 list、dict、set 不能作为键，tuple 在元素都可哈希时可以。

## 4. 函数与参数传递

Python 的参数传递方式是"对象引用传递"，也叫传共享对象。函数收到的是实参对象的引用，不是副本。因此在函数内修改可变对象（如向列表 append）会影响外部；而对形参重新赋值只是让局部名字指向新对象，不影响外部。

参数分为位置参数、默认参数、可变位置参数 `*args`、可变关键字参数 `**kwargs`。参数顺序必须是：位置参数、默认参数、`*args`、仅关键字参数、`**kwargs`。

默认参数只在函数定义时求值一次，所以不能用可变对象作默认值。`def f(x, lst=[])` 会让多次调用共享同一个列表，正确写法是 `lst=None` 后在函数体内初始化。

## 5. 装饰器

装饰器本质是一个接收函数并返回新函数的高阶函数，语法糖 `@decorator` 等价于 `func = decorator(func)`。它的作用是在不修改原函数代码的前提下，增加日志、计时、权限校验、缓存等横切逻辑。

带参数的装饰器需要三层嵌套：最外层接收装饰器参数，中间层接收被装饰函数，最内层是实际执行的包装函数。包装函数通常用 `functools.wraps` 保留原函数的名称与文档字符串，否则调试和文档生成会丢失信息。

常见内置装饰器有 `@staticmethod`、`@classmethod`、`@property`。其中 `@property` 把方法伪装成属性访问，用于在读取属性时做校验或惰性计算。

## 6. 生成器与迭代器

可迭代对象实现了 `__iter__`，迭代器同时实现了 `__iter__` 与 `__next__`。`for` 循环的本质是先调用 `iter()` 拿到迭代器，再不断调用 `next()`，直到抛出 `StopIteration`。

生成器是写迭代器最简便的方式，函数体内出现 `yield` 即成为生成器函数，调用它不会执行函数体，而是返回一个生成器对象，每次 `next()` 执行到下一个 `yield` 暂停并保留现场。

生成器的价值是惰性求值与低内存占用。读取大文件时逐行 `yield`，内存里始终只有一行；而 `readlines()` 会把整个文件读进内存。生成器只能遍历一次，需要重复使用时应当缓存结果或改用列表。

## 7. 异常处理

异常处理使用 `try / except / else / finally`。`else` 在 try 块没有异常时执行，`finally` 无论是否异常都会执行，常用于释放文件、连接、锁等资源。

捕获异常应当尽量精确，避免裸 `except:`，否则会把键盘中断和系统退出也吞掉，掩盖真正的错误。需要保留原始堆栈时用 `raise ... from e`。

自定义异常通常继承 Exception，并在异常类中携带业务上下文。工程实践中，异常应该在能处理它的层级被捕获，不能处理的就向上抛，不要为了"看起来不报错"而静默吞掉。

## 8. 面向对象与魔术方法

Python 支持封装、继承、多态。命名以单下划线开头表示约定内部使用，双下划线开头会触发名称改写，实现一定程度的私有化。

魔术方法让自定义类融入语言特性。`__init__` 负责初始化，`__str__` 面向用户展示，`__repr__` 面向调试，`__len__`、`__getitem__`、`__iter__` 让对象支持长度、下标与遍历，`__eq__` 与 `__hash__` 决定相等性与可哈希性。

继承时注意 `super()` 的调用顺序，多重继承遵循 MRO（方法解析顺序），可用 `类名.__mro__` 查看。组合优于继承，当关系不是明确的"是一种"时，优先用组合降低耦合。

## 9. 上下文管理器

`with` 语句用于确保资源被正确释放。实现了 `__enter__` 与 `__exit__` 的对象即为上下文管理器，进入 with 时调用前者，退出时无论是否异常都调用后者，异常信息会传给 `__exit__`，返回 True 可抑制异常。

用 `contextlib.contextmanager` 配合生成器可以更简洁地写上下文管理器：`yield` 之前的代码相当于 `__enter__`，之后的代码相当于 `__exit__`，异常在 `yield` 处抛出，用 try/finally 保证清理。

典型场景包括文件读写、数据库事务、临时切换目录、加锁、计时。

## 10. GIL 与并发模型

CPython 解释器有全局解释器锁（GIL），同一时刻只允许一个线程执行 Python 字节码。因此多线程无法利用多核做 CPU 密集计算，但 I/O 操作会释放 GIL，所以多线程适合网络请求、文件读写这类 I/O 密集任务。

CPU 密集任务应使用多进程 `multiprocessing`，每个进程有独立的解释器和 GIL，能真正并行，代价是进程创建开销与进程间通信成本。

异步编程 `asyncio` 用单线程事件循环处理大量并发 I/O，通过 `async def` 与 `await` 在等待点让出控制权。它不适合包含阻塞调用的场景，一旦在协程里调用同步阻塞函数，整个事件循环都会卡住。

## 11. 内存管理与垃圾回收

CPython 采用引用计数为主、标记清除与分代回收为辅的策略。每个对象维护引用计数，计数归零立即释放，这是确定性回收，优点是及时。

引用计数的缺点是处理不了循环引用，所以引入标记清除，定期从根对象出发标记可达对象，未标记的回收。分代回收基于"大部分对象生命周期很短"的假设，把对象分为三代，新对象在第 0 代，活得越久晋升越高代，越少被扫描。

可以用 `gc` 模块手动触发或调整阈值。`__del__` 方法在对象被回收时调用，但不应依赖它做关键清理，因为回收时机不确定。

## 12. 常用标准库与工程实践

高频标准库包括：`os` 与 `pathlib` 处理路径，`json` 处理序列化，`datetime` 处理时间，`collections` 提供 deque、Counter、defaultdict，`itertools` 提供排列组合与惰性迭代工具，`logging` 做分级日志，`argparse` 解析命令行参数，`typing` 提供类型标注。

工程实践上，建议用虚拟环境隔离依赖，用 `requirements.txt` 或 `pyproject.toml` 固定版本，用类型标注提升可读性，用日志替代 print，用配置文件或环境变量管理密钥，避免把密码写进代码。
