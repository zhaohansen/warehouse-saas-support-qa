你是一个数据标注系统，为「学科知识问答助手」生成意图分类训练数据。

【项目背景】
这是一个面向 Python、Java、AI、MySQL、Redis 等学科的个人知识问答工作台。
用户可以提问，也可以上传自己的课件、讲义、PDF、教材扫描件作为资料库。
系统的回答顺序是：标准 FAQ → 本地资料检索 → 检索未命中时用模型自身知识作答。
本分类器的作用是：判断一个问题**是否需要查阅用户上传的本地资料**。

【两个类别】
1. 通用知识
   - 不依赖任何本地资料，模型自身知识即可回答的学科问题。
   - 包括：概念解释、原理机制、两者区别、代码实现、报错排查、数学计算、复杂度分析、应用场景。
   - 示例：
     "Python 的生成器和迭代器有什么区别？"
     "MySQL 索引失效的常见原因有哪些？"
     "用 Python 写一个带重试的请求函数"
     "快速排序的时间复杂度是多少？"

2. 学科资料
   - 必须查阅用户导入的课件/讲义/PPT/教材/笔记/资料库才能回答的问题。
   - 判据是：问题里出现了对本地材料的指代（第几章、哪一页、课件、讲义、我上传的、
     老师说的、复习提纲、实验指导书、上次的作业等）。
   - 示例：
     "课件第三章讲的索引优化是什么？"
     "我上传的 Redis 笔记里，持久化那部分怎么写的？"
     "复习提纲里动态规划是重点吗？"
     "实验指导书第 5 步要求做什么？"

【关键约束】
1. 两个类别数量必须严格相等，各占 50%。
2. 两类**共用同一主题池**（同样的技术主题都要出现在两个类别里），
   区别只在于"是否指向本地资料"。不要让"MySQL"这类词成为某一类的标志。
3. 严禁出现培训机构业务话术：学费、报名、招生、就业、师资、校区、优惠、试听、证书（非技术语境）、包就业等。
4. 句式要多样：长短句混合、书面语与口语混合、可加"请问/想请教一下"等前缀，
   也要有省略主语的简短问法（如"第三章讲啥了"）。
5. 同一句式不得占比过高，避免模型学到模板而非语义。
6. 每条数据格式为一行 JSON（JSONL）：
   {"query": "用户问题原文", "label": "通用知识" 或 "学科资料"}

【输出要求】
- 输出 JSONL，每行一条，不要额外解释文字。
- 生成后自检：两类条数是否相等、是否有重复、是否残留培训销售词、是否有空值。

现在开始生成，目标 5000 条（每类 2500 条）。
